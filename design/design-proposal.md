# OpenCode 额度 · 视觉与信息层级优化方案

> 说明：本文是设计方案，不含实现改动。预览图 `preview-dark.png` / `preview-light.png` 用 DSH 真实主题 token（`--dsw-alias-*`）按 1:1 尺寸渲染，示例数据为 5h 94% / 本周 93% / 本月 33%（本月按当前速度预计 118%）。
> 三套方案都只改 `client.js`（渲染 + CSS），Host 半、数据接口、预测算法、偏好存储完全不动。

> **决策记录（2026-11-10）**：采用 **A · 冷静仪表**，并按反馈把「预计用到 X%」作为每个窗口的常驻第四要素（三个数字都需要读，本月预计最终消耗量同样重要）。该版本已落地到 `client.js`，见文末「七、落地情况」。

---

## 一、现状诊断

当前页面像一份「说明文档」，而不是一个「仪表」。具体问题：

| # | 问题 | 证据 |
|---|---|---|
| 1 | **文字承担了本该由图形承担的信息** | 页面可见文案约 36 段（含数字），其中 7 段是方法/来源说明；三个窗口各用 6 行文字表达"还剩多少、用了多少、何时重置、几点重置" |
| 2 | **层级扁平** | 标题 16px、卡片名 13px、指标 22px、说明 11px、辅助 11px；主次只靠 22px 一个数字撑，视线没有落点 |
| 3 | **重复** | 同一窗口同时给出「已用 67%」「剩余 33%」「重置 12天4小时」「2026/11/23 00:00:00」，其中绝对时间是倒计时的重复表达 |
| 4 | **解释性文字占据黄金位置** | 「按本周期平均消耗外推，突发用量不参与计算」「数据来自 opencode.ai，每 5 分钟自动刷新」「关闭后只保留侧边栏入口…」——这些是**第一次使用才需要**的信息，却每次都在抢注意力 |
| 5 | **三张同构卡片 = 没有重点** | 真正需要一眼看到的只有「哪个窗口最紧 + 会不会超额」，但三个窗口视觉权重完全相同 |
| 6 | **预测没有视觉形态** | 预测是整个插件最有价值的信息，却只是三张灰底小卡的第三行文字；超额时只有一行红字 |
| 7 | **颜色只做点缀** | 状态色只出现在小圆点 / 进度条 / 数字上，没有形成"整体氛围 = 安全 / 偏紧 / 危险"的第一印象 |
| 8 | **占屏偏高** | 内容高度约 660px，主面板稍矮就要滚动；徽章三个 chip 又占去输入框上方一整行 |

**一句话**：现在用户要"读"额度；应该改成"看"额度。

## 二、设计原则（三套方案共用）

1. **形状 > 数字 > 文字**：能用一个环/一条线表达的，绝不再写一句话。文字只保留「窗口名 + 数值 + 倒计时」三个必要标签。
2. **一屏一个焦点**：页面必须能回答"最要紧的是哪个窗口"，其余信息降为次要层级。
3. **说明文字退到 hover**：方法、来源、刷新频率、绝对重置时间全部放进 `title` / 悬浮卡片；
   常驻文案里不出现解释性句子（空状态、错误态除外，那里文字是必要的）。
4. **只用主题 token**：颜色全部走 `--dsw-alias-*`，暗色/浅色自动适配；不引入硬编码色值。
5. **动效克制**：只有数值变化用 350ms 过渡，环/条不做循环动画，避免在聊天界面里抢注意力。

## 三、三个方案

### 方案 A · 冷静仪表（Calm Instrument）

**气质**：像手表表盘 / 音频电平表——精密、安静、可信。

**页面结构**

```
OpenCode 额度                                    18:30 更新  ↻
┌─────────────────────────────────────────────────────────┐
│      5 小时            本周              本月            │
│    ◯ 94%             ◯ 93%            ◯ 33%             │
│      剩余              剩余              剩余            │
│   2 小时30分后重置   6 天3小时后重置   12 天4小时后重置   │
│                                         [预计超额]       │
└─────────────────────────────────────────────────────────┘
[输入框徽章                                        ●───○]
数据来自 opencode.ai                          每 5 分钟自动刷新
```

- 三个同构环形表盘并排：`150px` 环、`8px` 描边、圆头端点；环填充 = **剩余百分比**（"油箱"隐喻，满环 = 满额），颜色随剩余比例取 `success / warn / error`。
- 环心：`34px/600` 数字 + `13px` `%` + `10px` 字距 `1px` 的「剩余」。
- 环下：`11.5px` 倒计时，时间数字用 `label-primary`、单位与"后重置"用 `label-secondary`。
- 预测只做一件事：**会超额时**在该窗口下方出现一枚红色 `预计超额` 药丸（`10px`，背景 = error 13% 透明）。不会超额、或窗口刚开数据不足时，**什么都不显示**——这比现在写「数据不足 / 周期长度未确认」干净得多。
- 页脚只留一行来源与刷新说明；`18:30 更新` 移到标题行右侧，刷新按钮改成 24px 图标按钮。
- 侧边栏图标右上角加一个 `5px` 状态点（取最紧张窗口的颜色），不进页面也能感知。

**文字量**：36 段 → 约 16 段，说明性文字 0 段。

**优点**：三窗口权重一致，适合"三个窗口同等重要"的心智；最像 DSH 原生控件，视觉风险最低；环形对"比例"的表达最直观。
**代价**：三个等权环仍然要"读三个数"才知道哪个最紧；信息密度偏低，页面中部会有较多留白。
**实现要点**：SVG `circle` + `stroke-dasharray`（`r=60`，周长 377，`dash = 377 × 剩余%`），`rotate(-90deg)`；纯展示，无新增数据需求。

### 方案 B · 主角突出（Hero + Rows）— 推荐

**气质**：卡片式仪表盘，一个主角 + 两行清单；像机票 App 的"next trip"。

**页面结构**

```
OpenCode 额度                                 18:30  [刷新]
┌─────────────────────────────────────────────────────────┐
│ ● 本月 · 最紧张                       按当前速度，期末   │
│ 33% 剩余                                    118%         │
│ 12 天 4 小时后重置                         会超出配额     │
│ ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░  ← 斜纹 = 会被用掉     │
└─────────────────────────────────────────────────────────┘
5 小时   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░   94%      2 小时 30 分
本周     ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓░   93%      6 天 3 小时
[输入框徽章                                        ●───○]
```

- **自动选主角**：三个窗口中"剩余最少 / 预计超额 / 即将重置"权重最高的一条放大成 hero（`52–58px` 数字），其余两条收成单行（`13.5px` 数字 + `5px` 细条 + 倒计时）。
- hero 背景 = `tone` 色 7% 混入 `bg-layer-1`，右上角 `16%` 径向渐变高光；边框 `tone 24%`。危险时整体泛红、安全时泛绿——**整块卡片的色温就是状态**。
- hero 的进度条用斜纹表达预测：实心段 = 当前剩余（33%），斜纹段 = 「按当前速度，重置前会被用掉的部分」。这样"数字（剩余）"和"图形（预测）"在同一根条上共存，不需要额外文字说明。
- 预测数字只保留在 hero 右上角，且只有 `willExceed` 时用 error 色 + 「会超出配额」四字；不会超额时该位置留空。
- 徽章同步改成**一枚胶囊**：`⚠ 本月剩 33% · 12 天`，只报最紧张的一条，点击展开面板。比三个 chip 省一半宽度，也把"注意力"收敛到一个点。

**文字量**：36 段 → 约 16 段（其中 hero 占 6 段）。
**动态稳定性**：主角切换加 200ms 淡入，且只在"明显更紧"（差值 ≥ 10 个百分点或状态变化）时切换，避免刷新时来回跳。
**优点**：**最直观**——不用读三个数就知道该担心哪个；预测第一次有了视觉形态；信息密度合适。
**代价**：主角会随用量变化而变，需要一个稳定的切换策略；hero 卡片比其他部分"重"，和 DSH 极简风格稍有反差。
**实现要点**：`pickFocus(windows)` 选主角（排序：`willExceed` > 剩余低 > 重置近）；hero 条 = 剩余段 + 斜纹覆盖段；斜纹用 `repeating-linear-gradient`；无需新增接口。

### 方案 C · 排印极简（Typographic Minimal）

**气质**：瑞士排版 / 规格表——无卡片、无边框，只有字阶、细线和留白。

**页面结构**

```
额度                                       18:30 · OPENCODE.AI
5 小时                                                         94% 剩余
2 小时 30 分后重置                          ───────────────────────
5 小时                                                         93% 剩余
6 天 3 小时后重置                            ───────────────────────
本月                                                           33% 剩余
12 天 4 小时后重置                          ──────░░░░░░░░░░░░░░░░░
[输入框徽章                                        ●───○]
```

- `580px` 居中窄栏；每行：左上是窗口名（`11.5px` 字距 `0.6px`）+ 倒计时，右下是 `46px/300` 大数字，底部一条 `1.5px` 细线作为全部图形语言。
- **常规行整体无彩色**：只有"剩余低"的那一行数字变 warn/error 色，其余全用 `label-primary`——颜色成为唯一的异常信号。
- 预测在细线上表达：本月条的 `33%→100%` 段染成极淡红（error 26%），表示"剩下这段会在重置前被用掉"。
- 页面标题缩成 `11.5px` 全大写小标签「额度」，与 DSH 的设置页风格一致。

**文字量**：36 段 → 约 15 段，图形元素接近 0，几乎全靠排版。
**优点**：最安静、最不容易和未来 DSH 改版冲突；实现成本最低；大数字的"阅读速度"其实最快。
**代价**：状态感最弱（只有一条横线描述 33%），"还有多少"需要靠数字而非图形；对不熟悉的人可能显得"没设计"。
**实现要点**：几乎纯 CSS；`font-variant-numeric: tabular-nums` + `font-weight:300` 保证数字不抖；一条 `position:absolute` 的底线。

### 附加：徽章（输入框上方）三种取舍

| 方案 | 形态 | 特点 |
|---|---|---|
| 现状 | 三个带边框 chip：`● 5h 94%  ● 周 93%  ● 月 33%` | 占宽、三个同等权重 |

## 四、推荐

**主推 B（主角突出）**，理由：

1. 它直接回答用户唯一真正想问的问题——「**哪个窗口要当心了**」，而不是让用户自己在三张卡里比较；
2. 预测（本插件最有价值的能力）第一次有了视觉形态（斜纹 + 色温），不再是灰色小字；
3. 文案删到 16 段后仍保留完整语义（窗口名 / 剩余 / 倒计时 / 超额），没有信息损失——被删的都是"读一次就够"的说明。

**次选 A**：如果希望三个窗口被平等对待、并且页面气质尽量贴近 DSH 原生控件，选 A 最稳。
**C 适合**：希望额度页"隐形"、只在异常时说话的用户。

**建议的实施顺序（分两批，降低风险）**

1. **第一批（低风险，半天）**：先做"减法"——删 subtitle / 预测方法说明 / 设置说明 / 页脚长句，把细节挪进 `title`；徽章按 A 或 B 的形态收成一条；侧边栏图标加状态点。这一步不改布局，立刻能感知"清爽"。
2. **第二批（主方案）**：按选定的 A / B / C 重写 `QuotaPanel` 的渲染与 CSS，`ForecastSection` 合并进各窗口（只保留"会超额"信号），`BadgeSwitch` 收成一行。`client.js` 里 `WINDOWS`、`toneFor`、`describeCountdown` 可复用，改动集中在视图层。

## 五、必须一并处理的细节

- **细节去哪了**：已用 %、绝对重置时间、平均速率、周期假设（本月按 30 天）全部放进 `title` 悬浮提示；键盘用户用 `aria-label` 提供同样内容，不能只靠 hover。
- **状态色语义**：统一「剩余」视角——>=50% success、20–50% warn、<20% error；预测超额用 error 徽标，且**只在可靠时**显示（`reliable === true`），避免窗口刚开就报红。
- **空/错误态**：保留现有具体错误文案（缺凭证 / 401 / 超时 / 网络），但用"一行标题 + 一个图标 + 一个重试按钮"的形态，而不是现在的整块红色文字卡。
- **动画**：环/条宽度 350ms ease；hero 切换 200ms 淡入；`prefers-reduced-motion` 下全部关闭。
- **浅色主题**：卡片/面板在浅色下依赖 `border-l1`（4% 黑）边界偏弱，建议面板改用 `border-l2`；A 的环轨道在浅色下需用 `bg-layer-2`（浅色主题里它就是浅灰）才可见。
- **不要做的事**：不做实时 sparkline（Host 没有历史样本，伪造曲线会误导）；不把三个窗口做成可切换 tab（多一次点击，违背"一眼看完"）。

## 七、落地情况（A 方案 + 预测行）

已按 A 实现到 `client.js`，与设计中唯一的差异是：**每个环下常驻一行「预计用到 X%」**（不只在超额时出现），会超额时数字变红；窗口刚开始、Host 给不出可靠预测时这一行不出现，原因写进悬浮提示。

实现要点：

- **环**：SVG `circle`，`r = 60`、`stroke 8`，弧长 = 周长 × 剩余比例，`stroke-dasharray` 带 350ms 过渡；环心是 31px 剩余百分比 + 10px「剩余」。
- **状态色**：按剩余比例（≥50 绿 / 20–50 黄 / <20 红），环、徽章圆点、侧边栏状态点共用同一个 `toneFor`。
- **预测行**：`预计用到 {round(projectedPercent)}%`，`willExceed` 时用 error 色；`used %`、精确重置时间、平均速率、30 天假设全部进 `title`。
- **徽章**：三枚 chip 收成一枚胶囊（发丝线分隔三段），点击打开额度页。
- **侧边栏图标**：右上角 5px 状态点，取最紧张窗口的颜色。
- **版式**：标题在顶、表盘 + 开关在剩余空间垂直居中、页脚贴底；宽度 <600px 时表盘改为单列。
- **深浅色**：全部走 alias token；环轨道用 `label-secondary` 22% 透明度，避免浅色主题下轨道与白底同色而消失。

**验证方式**：把 `client.js` 装进一个假模块加载器，用真实 React 18 + `ReactDOMServer` 渲染实际组件，再套 DSH 真实 token 截图。已覆盖：暗色正常态、浅色正常态、错误态（401 + 重试）、加载态、窄面板单列布局。截图见 `design/_verify/s-dark-ok.png`、`s-light-ok.png`、`s-dark-error.png`。浏览器端与 SSR 的差异（React 转义 `>`、`""`）只在验证脚本里处理，生产代码里 `StyleTag` 由 DOM 直接写 `textContent`，不受影响。

## 八、第二轮调整（按使用反馈）

反馈三条：① 细节不该只靠悬浮，应该在视觉中心下方常驻；② 视图居中显得整页太空，不该占一整页；③ 三枚徽章位置不对，应该在模型选择框左侧，并且没选 OpenCode Go 时不该出现。另外截图显示浅色主题下徽章开关完全看不见。

对应改动：

| 反馈 | 处理 |
|---|---|
| 细节常驻 | 环下新增 **明细表**：窗口 / 已用 / 平均速率 / 重置时间，外加一行口径说明（速率 = 已用 ÷ 周期已过时间；本月按 30 天估算时注明）。悬浮提示保留，但不再是唯一入口。 |
| 整页太空 | 去掉垂直居中与 `safe center`，内容改为顶部起排、`max-width: 760px`，仪表 + 明细 + 开关 + 页脚把页面撑满；≤640px 时仪表改单列、明细表隐藏"重置时间"列。 |
| 徽章位置 | 从 `conversation.input.dock`（输入框上方整行）迁到 **`conversation.input.right`**——插槽树里它正好排在模型选择框之前，渲染成一条与工具栏同高的轻量读数。 |
| 只在 OpenCode Go 下出现 | 徽章用插槽标准属性 `useProjection('modelSelection')` 读取当前会话选择（`next ?? lastUsed`），`provider !== 'opencode-go'` 时直接返回 `null`。 |
| 开关不可见 | 关闭态轨道原来用 `bg-layer-2`（浅色主题下与卡片同色，等于白底白开关）。改为 `label-secondary` 38% 的混色轨道 + `bg-base` 滑块 + 阴影，两种主题都可见。 |

第二轮验证截图：`design/_verify/s2-dark.png`、`s2-light-ok.png`、`s2-dark-error.png`、`s2-dark-narrow.png`（含"模型 = DeepSeek 时徽章不渲染"的对照行）。

## 九、第三轮调整（按使用反馈）

反馈三条：① 明细表下的速率口径说明挤成一行，可读性差；② 首页（新任务页）输入框旁没有徽章；③ 徽章 hover 的原生提示是一串文字，不优雅，建议改成悬浮后显示数据环的小卡。

| 反馈 | 处理 |
|---|---|
| 说明分行 | `.ocq-detail-note` 改为两行：第一行「平均速率 = 已用量 ÷ 本周期已过时间」，第二行「窗口刚开始时不估算」（`assumedSpan` 时追加「本月按 30 天估算」）；locale 拆成 `detail.note.rate` / `detail.note.scope`。 |
| 首页徽章 | 原因：`modelSelection` 投影在空白会话里是 `{lastUsed:null, next:null}`，徽章直接 `return null`；而模型选择框此时显示的是 Host 目录默认值。修法：徽章按 `next → lastUsed → Host 目录默认值` 的顺序取当前模型——默认值经 `ctx.inject(['remote','remote.session'])` 调 `session.modelCatalog()` 读一次（`connection/reset` 后重读），与模型选择框的口径完全一致。 |
| 悬浮改小卡 | 去掉原生 `title`（含错误态），改为 hover intent（260ms）+ 键盘 focus 触发的 portal 浮层：三枚迷你环（`QuotaRing` 增加 `compact` 参数，环长仍是剩余额度）、重置倒计时、「预计用到 X%」，底部一行「点击徽章查看额度明细」；`Esc` / 移出 / 滚动 / resize 关闭。浮层 `position:fixed` 并 portal 到 `document.body`（docked composer 会裁剪固定浮层），右对齐贴在徽章上方，空间不足时翻到下方。 |

**为什么选悬浮小卡而不是保留文字提示**：徽章本来就只有数字、没有"形"，迷你环与额度页同一套环语言，能把解释性文字从页面挪进浮层；但触屏没有 hover，所以 focus 版本是必须的，悬浮卡本身不做交互（点击仍走徽章进额度页）。

**验证方式**：`node --check client.js` 语法通过；`cordis_inspect` 的 Client `Slots` 确认 `conversation.input.right` 上 `opencode-quota` 仍处于 active；视觉验证依赖用户刷新页面后目测（本机无浏览器控制权，未做截图）。首页徽章的行为等价于模型选择框的 `next ?? catalog.default`，两条路径读的是同一个 Host 目录值。
